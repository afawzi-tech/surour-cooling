# دليل الإعداد خطوة بخطوة

هذا الدليل لربط التطبيق بقاعدة بيانات Supabase وتشغيله بأمان. لا يحتاج خبرة برمجية.

## 1. إنشاء مشروع Supabase
1. ادخل إلى https://supabase.com وسجّل حساباً مجانياً.
2. اضغط **New project**، واختر اسماً (مثلاً `surour-cooling`) وكلمة مرور قوية لقاعدة البيانات، ثم اختر أقرب منطقة (مثلاً Frankfurt).
3. انتظر دقيقتين حتى يجهز المشروع.

## 2. إنشاء الجداول وقواعد الصلاحيات
1. من القائمة الجانبية افتح **SQL Editor**.
2. افتح الملف `supabase/schema.sql` من المستودع، وانسخ محتواه كاملاً.
3. الصقه في المحرر واضغط **Run**. يجب أن تظهر رسالة Success.

## 3. إيقاف التسجيل الذاتي (مهم للأمان)
- **Authentication → Sign In / Providers → Email**: أطفئ خيار **Allow new users to sign up**.
- بهذا لا يستطيع أي شخص إنشاء حساب بنفسه، والمدير وحده يضيف المستخدمين.

## 4. إنشاء حساب المدير
1. **Authentication → Users → Add user → Create new user**.
2. اكتب بريدك وكلمة مرور قوية، وفعّل **Auto Confirm User**.
3. ارجع إلى **SQL Editor** وشغّل هذا الأمر بعد تغيير البريد إلى بريدك:
   ```sql
   update public.profiles set role = 'admin'
   where id = (select id from auth.users where email = 'you@example.com');
   ```

## 5. ربط التطبيق بالمشروع
1. **Project Settings → API**، وانسخ:
   - **Project URL**
   - مفتاح **anon public**
2. افتح الملف `js/config.js` وضع القيمتين مكان `YOUR-PROJECT` و`YOUR-ANON-KEY`.

> ⚠️ لا تنسخ مفتاح **service_role** أبداً، ولا تضعه في أي ملف أو رسالة. مفتاح anon آمن للنشر لأن الحماية في قواعد RLS على الخادم.

## 6. إضافة بقية المستخدمين
- أضِف كل مستخدم من **Authentication → Users → Add user** (مع Auto Confirm).
- يظهر تلقائياً في صفحة **المستخدمون** داخل التطبيق بدور "فني"، وتغيّر دوره أو اسمه أو تعطّله من هناك.

## 7. نقل البيانات القديمة
البيانات القديمة محفوظة في متصفحك فقط. لنقلها:
1. افتح النسخة القديمة من التطبيق في المتصفح نفسه الذي استخدمته سابقاً، واذهب إلى **النسخ الاحتياطي** وانسخ النص.
2. افتح التطبيق الجديد ← **النسخ الاحتياطي** ← الصق النص في خانة الاستيراد ← **استيراد**.
3. المشاريع القديمة تدخل بدون براند، فافتح كل مشروع واختر له البراند (LG أو Midea) من زر **تعديل**.
4. الاستيراد يضيف المشاريع ولا يحذف شيئاً. لا تستورد الملف نفسه مرتين حتى لا تتكرر المشاريع.

## تحديث قاعدة بيانات موجودة
إذا شغّلت `supabase/schema.sql` سابقاً، شغّله مرة ثانية بعد كل تحديث. الملف آمن لإعادة التشغيل ويضيف الأعمدة الجديدة (مثل البراند) بدون حذف البيانات.

## الأدوار والصلاحيات
| الإجراء | مدير | مشرف | فني |
|---|:-:|:-:|:-:|
| عرض المشاريع والمراحل والمواد | ✓ | ✓ | ✓ |
| تحديث المراحل (الحالة، الكوادر، التواريخ، الملاحظات، الجاهزية) | ✓ | ✓ | ✓ |
| رؤية قيمة العقد | ✓ | ✓ | — |
| إنشاء العقود وتعديلها | ✓ | ✓ | — |
| إضافة المواد وحذفها | ✓ | ✓ | — |
| النسخ الاحتياطي | ✓ | ✓ | — |
| حذف المشاريع | ✓ | — | — |
| التبليغ عن بدء أو إكمال مرحلة مسندة لفرقته (مع صورة) | — | — | ✓ |
| الموافقة على تقارير الفنيين أو رفضها | ✓ | ✓ | — |
| إدارة المستخدمين وسجل العمليات | ✓ | — | — |

هذه الصلاحيات تُفرض داخل قاعدة البيانات نفسها، فحتى لو عدّل أحد كود الصفحة لن يتجاوزها.

## ملاحظات أمنية
- لا يوجد نظام محمي 100% من الاختراق. الإجراءات المطبّقة تقلّل الخطر كثيراً لكنها لا تلغيه.
- استخدم كلمات مرور قوية ومختلفة، وعطّل حساب أي موظف يغادر فوراً.
- صدّر نسخة احتياطية دورياً واحفظها في مكان آمن، لأنها تحتوي بيانات العملاء.

## تقارير الفنيين بالصور
1. من صفحة **المستخدمون** اختر لكل فني **فرقته** (فرق الشركة فقط).
2. أسند المراحل للفرقة كالمعتاد من صفحة المشروع.
3. يفتح الفني المشروع من هاتفه، ويضغط **أبلغ أن العمل بدأ** أو **أبلغ أن المرحلة اكتملت** (الصورة إجبارية عند الإكمال).
4. يظهر التقرير للمدير والمشرف في لوحة التحكم تحت **تقارير بانتظار موافقتك**. الموافقة تحدّث المرحلة (والإكمال يبدأ التالية)، والرفض يحتاج سبباً يراه الفني.
- الصور في مخزن خاص `stage-photos` في Supabase (ليس عاماً)، تُصغَّر في الهاتف قبل الرفع، وحدها 5 ميغا.
